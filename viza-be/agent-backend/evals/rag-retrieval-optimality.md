# “最优”证明与比较方法 — 2026-09-14

本次已证明一个有限范围内的**经验最优**：冻结仓库语料、122 条已见合成题和真实向量，在已有 7 种分块方案、全部整数 `k=1..12`、`threshold∈[0,1]` 内，先要求所有正例的标注证据完整召回，再最大化下文的评分。最优方案是 **400 字符分块、80 字符 overlap、k=7**。

这不是“对未来用户也最优”的证明。三轮独立验证的失败记录仍然有效；本次将全部已见题合并做描述性穷尽分析，没有新保留集，不能用它推翻此前发布门槛或将参数直接推广到线上。

机器可核查结果见 [完整证书](rag-retrieval-optimality-certificate.json)，实现见 [穷尽搜索脚本](../scripts/prove-rag-retrieval.ts)，此前的独立验证见 [实验报告](README.md)。

## 1. “最佳”先有明确目标

设 `R` 为去重后相关来源数，`S` 为取回来源数，`H` 为已完整覆盖的标注证据条数，`E` 为标注证据总数。每道正例：

```text
precision = R / S
recall = H / E
F2 = 5 × precision × recall / (4 × precision + recall)
   = 5RH / (4RE + HS)
```

空结果或没有证据命中时 F2 为 0。多个 overlap 片段属于同一个国家/parent 来源，只计一票；证据可以由多个相邻片段共同覆盖，但原文区间有缺口就不算完整命中。例如，1 个相关来源混在 3 个取回来源中，且必要证据全覆盖时，precision=1/3、recall=1、F2=5/7。

本次比较规则依次是：

1. **可行性约束**：85 道正例中，每道题的每条标注证据都必须完整覆盖，共 111 条证据；任何遗漏都淘汰。
2. **主目标**：`J = 0.7 × 正例 macro F2 + 0.3 × 负例空结果率`。37 道负例只要取回任何片段，就算误召回。正例与负例分别平均后加权。
3. **同分选择**：更少总上下文字符、更小 k、分块名称排序、较低的区间代表阈值。主目标并列区间全部保留；区间内上下文和检索 ID 不一定相同，JSON 中 metrics 只对应其 candidate 代表点。

这些权重和约束是明确的业务取舍，不是客观定律。若撤掉“完整召回”约束，同一题集会选出 `1600/0、k=1、threshold≈0.561`，J 提高到 0.752775，但 **22 道正例漏证据**，macro recall 只有 76.08%。所以只报最高综合分会掩盖重要失败。

## 2. 怎样做到穷尽，而不是只试几个数字

语料为 61 个 country 文件、159 个 documents、559 个原始 chunks。七种分块为原始语义块，以及 400/800/1600 个 Unicode code points 各配 0%/20% overlap；不跨原始 chunk 合并。每块使用实际摄入格式，包括重复 metadata，embedding 为已缓存的 `text-embedding-3-small` 1536 维向量。没有新增 provider 或数据库调用。

对每种分块、每道题，固定 cosine 分数和排序。检索条件是 `score >= threshold`。设相邻分数断点为 `a < b`，当阈值位于 **`(a,b]`**，每个片段是否通过筛选完全相同。因此检索结果、intent fallback、指标都不变。只需评估每个区间的右端点 b，再包括 threshold=0 的单点和终点 1，就覆盖了整个 `[0,1]`，无需以 0.01 或 0.05 步长采样。

为降低计算量，每道题保留 broad 排名与 document-type 排名各前 12 项。证明如下：某个池内排第 13 以后的片段，如果通过阈值，则排在它前面的 12 项也通过，因而它不可能进入 `k≤12` 的结果；如果前面的项未通过，更低分的项也不会通过。implicit intent 从 filtered 切到 broad 的断点是 filtered 最高分，也被保留。显式 document-type filter 始终不放宽。不能只保留 broad 前 12 项，否则可能遗漏类型过滤后的有效结果。

脚本另外将压缩排序与完整排序在**每道题的全部原始断点、全部 k** 上逐一比较，完成 **876,924 次检索 ID 序列一致性检查**，并断言语料 ID 唯一。

最终覆盖 **122,064 个分块/k/阈值区间组合**，其中 **8,716 个满足完整召回约束**。每种分块、每个 k 的最优值、不可行情况和并列区间都保存在 JSON。这里的组合数是分区单元数，部分单元可能产生相同检索结果。

比较分数使用 BigInt 有理数：F2 的整数分母不超过 `5 × 12 × 最大证据数`，用公倍数统一分母后精确比较 J，不依赖浮点小数近似判断谁赢。cosine 排名本身仍是本地 JS float64 运算；证书记录 Node/V8/ICU 版本、数据/语料/向量/代码 SHA-256 和枚举摘要。

因此，任意允许的配置都落在某个已检查区间，且该区间有同结果的代表点；所有可行代表点的精确 J 都不超过返回值。这就是本次有限范围内的最优性证明。它不是独立形式化验证器对整个程序的证明。

## 3. 与当前默认值如何比较

两列使用完全相同的 122 条题、标注规则和 metadata/intent 语义。它们是同一题集上的配对比较。

| 指标 | 当前基线：语义块、k=5、t=0.03 | 经验最优：400/80、k=7、t≈0.30277 |
| --- | ---: | ---: |
| 正例标注证据召回 | 100% | 100% |
| source precision | 31.86% | 34.27% |
| 正例 macro F2 | 0.674567 | 0.699107 |
| 负例误召回 | 35/37（94.59%） | 29/37（78.38%） |
| 主目标 J | 0.488413 | 0.554240 |
| MRR | 0.921569 | 0.913137 |
| 平均上下文字符 | 3,114.3 | 3,172.0 |

收益是 J 增加 0.065827、少 6 道负例误召回；代价是平均上下文增加约 1.85%，MRR 略降。因此它不是每一个指标都最好。误召回仍为 78.38%，也不能称为已解决无答案识别。

对 400/80、k=7，**主目标的整个最优阈值区间**是：

```text
0.29411446517946893 < threshold <= 0.3035156160781934
```

考虑同分后的上下文成本，脚本代表点是 `0.3027715206270639`，它所在的同结果区间为 `(0.30186447251733756, 0.3027715206270639]`，例如 `0.302` 会得到同样的结果。代表点保留长小数只是为了复现边界，不表示生产参数应精确到这些小数位；也不能把 `0.30` 写成唯一最优值。证书包含主目标区间两端及降低 k 后的反例检查。

具体反例：阈值刚超过上界，`RAG-ROBUST-005` 的爱沙尼亚受理渠道证据就被排除；同阈值把 k 从 7 降为 6，`RAG-CONFIRM-008` 的意大利多意图题就遗漏一项必要证据，虽然 J 反而升至 0.563956，仍因违反完整召回约束被淘汰。阈值恰在下界时没有漏证据，但多取回的非 gold 来源使 J 降至 0.552867。`t=0.30` 的主目标同样最优，平均上下文为 3,178.0，比代表点略长。

为什么是 k=7？在该分块方案下，k=1～6 对整个 threshold 范围都没有满足完整召回的配置。k=7～12 的各自最佳 J 依次为：

| k | 7 | 8 | 9 | 10 | 11 | 12 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 最佳 J | 0.554240 | 0.545416 | 0.542983 | 0.537659 | 0.534457 | 0.531060 |

为什么是 400/80？各分块方案都独立穷尽 k 与阈值，在相同完整召回约束下比较：

| 分块方案 | 最佳 k | 代表阈值（约） | 最佳 J | 平均上下文字符 |
| --- | ---: | ---: | ---: | ---: |
| 原始语义块 | 5 | 0.30617 | 0.540722 | 2,801.4 |
| 400 / overlap 0 | 7 | 0.30287 | 0.551462 | 2,984.3 |
| **400 / overlap 80** | **7** | **0.30277** | **0.554240** | **3,172.0** |
| 800 / overlap 0 | 5 | 0.29174 | 0.546032 | 2,651.5 |
| 800 / overlap 160 | 5 | 0.29174 | 0.546604 | 2,678.9 |
| 1600 / overlap 0 | 5 | 0.30633 | 0.543009 | 2,689.8 |
| 1600 / overlap 320 | 5 | 0.30633 | 0.544317 | 2,713.9 |

若更重视上下文成本，800/0 等方案可能更合适；该成本只参与当前评分的同分选择，并没有被作为主惩罚项。分块候选也没有涵盖 600 字符、其他 overlap 比例、token 分块、跨块合并或其他 embedding 模型。

将 F2 权重改为 0.5、0.7、0.9、1.0 时，当前约束下仍选择同一代表配置。由于每个候选的加权得分对权重是线性的，该配置同时在 0.5 和 1.0 两端最优，也就在整个 `[0.5,1]` 内主目标最优。该结论仍只针对同一题集、候选范围和完整召回约束，不能扩展到其它成本函数。

## 4. 证明的适用边界

- 122 条题全部已经参与过实验；本次是训练/已见数据上的经验最优，不存在新的独立验证结论。不把筛选后的提升或 bootstrap 当作无偏的生产提升估计。
- 标注是 agent 策划、以 seed 原文为证据的合成题，不是用户日志，也不是穷尽式相关性标注。未标为 gold 的来源可能同样有用。100% 召回指完整覆盖**标注证据**，不代表答案 100% 正确。
- 使用仓库 seed 快照和本地 exact cosine；未测线上 active release、数据库向量精度/ANN 近似误差、SQL 同分排序、生成答案、端到端延迟及用户满意度。阈值端点的精确结论不能直接套到线上数值实现。
- 只有 7 种固定分块和 k≤12；没有覆盖任意分块算法、模型或 k。有限样本也不能排除未来出现相关证据低于阈值的新问题。
- 所以运行时继续保留 `5 / 0.03 / seed-semantic` 基线。新的实证候选可以在冻结后进入人工审核的真实问题集及隔离索引验证；通过后才有依据更新默认值。此次不发布或重建线上索引。
